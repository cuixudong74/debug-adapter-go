# debug-adapter-go

进程内（in-process）脚本运行时调试服务。被调试目标与调试服务都运行在同一个
Go 进程内，不依赖任何外部服务或进程。编辑器插件与开发者控制台通过本服务提供的
Go API（或 JSON 线协议）完成断点、步进、栈变量查看与表达式求值。

## 架构

```
┌─────────────────────────────────────────────────────┐
│  编辑器插件 / 开发者控制台                            │
│         │                          │                │
│         ▼                          ▼                │
│  debug.Service  ──  protocol.Handler（可选 JSON）   │
│         │                                          │
│         ▼                                          │
│  debug.Session（实现 runtime.Hook）                  │
│    ├── 断点注册表（目标级，跨附加保留）               │
│    ├── 步进状态（任务级）                            │
│    ├── 事件队列（有界、有序、可关闭）                │
│    ├── 变量引用表（暂停期间有效，继续即失效）         │
│    └── 权限与审计                                    │
│         │                                          │
│         ▼                                          │
│  runtime.Target（脚本运行时）                        │
│    └── Task（执行单元，goroutine）                   │
│          └── Frame（调用栈帧）                       │
└─────────────────────────────────────────────────────┘
```

- **runtime**：确定性脚本运行时。任务逐行推进，每行执行前调用 `Hook.BeforeLine`；
  暂停时任务阻塞在钩子中，不推进、不影响其他任务。
- **debug**：调试服务核心。会话实现 `runtime.Hook`，负责断点命中判定、步进、
  事件下发、变量引用、求值、权限与审计。
- **protocol**：JSON 线协议层（DAP 风格），提供版本协商、向后兼容字段与请求分发。

## 会话生命周期

会话状态机：`running` ↔ `paused` → `terminated`；`detached` 为结束态。

| 操作 | 说明 |
|------|------|
| `Launch` | 创建目标并附加会话，目标立即运行 |
| `Attach` | 附加到已运行的目标。**互斥**：一个目标同一时刻只允许一个附加会话 |
| `Detach` | 分离会话。会话结束（不再收到事件），**目标继续按自身节奏运行，语义状态不受影响**；断点保留，重新附加后自动恢复 |
| `Terminate` | 终止目标并结束会话 |

语义规则：

- 已结束（`terminated` / `detached`）的会话不再收到任何事件（队列关闭）。
- 多个会话并发时各自操作不同目标，断点、步进、事件队列完全隔离。
- 目标终止（主任务正常结束或崩溃）时，会话进入 `terminated` 并收到 `terminated` 事件；
  崩溃事件带 `fatal=true` 与错误信息。

## 断点语义

- **行断点**：按 `(file, line)` 定位。命中判定在每行执行前进行一次，确定无重复。
- **条件断点**：命中时在当前帧作用域（局部变量 + 全局变量）求值条件表达式；
  条件为真才暂停。**求值失败不崩溃**：下发 `diagnostic` 事件，按「不命中」处理。
- **幂等**：在同一 `(file, line)` 重复设置返回同一断点（不重复创建）；
  删除不存在的断点是 no-op。
- **恢复策略**：断点注册表在目标级维护，`Detach` 不清除断点，`Attach` 后自动恢复；
  目标终止时随目标一起清除。恢复后命中计数持续累加，每次行进入只命中一次，
  不出现重复暂停。
- **异常断点**：过滤器 `none` / `uncaught` / `all`。脚本抛出未捕获异常时，
  若过滤器为 `uncaught` 或 `all`，任务在抛出现场暂停（`reason=exception`）；
  继续后任务终止。未设置异常断点时，未捕获异常直接终止任务。

## 步进语义

步进是**任务级**的，只影响被操作的执行单元：

| 操作 | 语义 |
|------|------|
| `StepIn` | 在下一行（含被调用函数内部）暂停 |
| `StepOver` | 帧深度不超过当前深度时暂停——不进入被调用函数 |
| `StepOut` | 帧深度小于当前深度时暂停——从当前函数返回后暂停 |

确定性规则：

- 暂停期间被暂停的任务阻塞在钩子中，**不推进**。
- 同一目标内的**其他任务不被误停**：步进只恢复目标任务，其余任务保持暂停或继续运行。
- `Continue` 恢复所有暂停的任务；`Step*` 只恢复目标任务。
- 步进在命中时清除；断点命中也会清除已武装的步进。

## 调用栈、帧与变量

- `Stack(taskID)` 返回调用栈（栈顶在前），每帧带 `id`、`name`、`file`、`line`
  与 `localsReference`。
- 变量通过 `variablesReference` 句柄惰性获取：`Variables(ref)` 返回子变量。
  - 对象 → 字段；数组 → 元素；帧 → 局部变量。
  - 嵌套结构按需展开，**惰性取值无副作用**。
  - 继续/步进后所有引用失效（旧引用返回 `not_found`）。
- `Evaluate(expr, frameID)` 在帧作用域求值表达式。表达式语言支持：
  字面量、标识符、字段访问 `.`、索引 `[]`、算术/比较/逻辑运算。
  **无赋值、无函数调用，求值不改变被调试程序的语义状态**。
- 求值失败返回可区分的错误（`EvalError`，子类型 `parse` / `notFound` / `type`），
  不会让会话崩溃。

## 权限规则

- 权限基于作用域（scope）：`variables:read`、`variables:read_sensitive`、
  `evaluate`、`session:control`。
- 敏感变量判定：字段显式标记 `Sensitive`，或名称匹配 `password` / `secret` /
  `token` / `credential` / `private_key` / `apikey` 等启发式规则。
- 越权读取（无 `variables:read_sensitive` 作用域）返回 `permission_denied`，
  **不返回变量值**，并写入审计日志。
- `Evaluate` 引用敏感名称同样需要 `variables:read_sensitive` 作用域。
- 所有权限相关操作（允许与拒绝）都记录到 `AuditLog`：时间、用户、动作、
  目标/会话、变量名、是否允许、原因。审计日志为有界内存环，可通过 `AuditSink`
  外接（如日志系统）。

## 事件

- 事件类型：`stopped` / `continued` / `terminated` / `thread` / `diagnostic`。
- 每个事件带会话级单调序号 `seq`；`Next(ctx)` 按 FIFO 顺序返回，支持上下文取消/超时。
- **有界队列**：容量 256。溢出时丢弃最旧的非关键事件并计数（`Dropped()`）；
  `terminated` 为关键事件，**永不丢弃**（必要时丢弃最旧非关键事件腾出空间）。
- 会话状态变更在锁内同步完成，事件仅作通知；乱序或重复事件不会让状态机错乱
  （状态只由 `Continue` / `Step` / `Detach` / `Terminate` 等操作驱动）。
- 取消与超时：所有请求接受 `context.Context`。取消/超时返回 `canceled` / `timeout`
  错误，会话保持一致状态（如 `Evaluate` 取消后会话仍 `paused` 且可继续求值）。

## 协议兼容

- 线协议版本 `1.0`。`initialize` 协商版本：主版本不匹配返回错误；
  客户端省略 `protocolVersion` 时按 `1.0` 处理。
- 新增字段一律为可选指针（如 `supportsSensitiveVariables`），旧客户端缺少字段时
  使用服务端默认值，正常工作。
- JSON 解码容忍未知字段（`json.Decoder`，不开启 `DisallowUnknownFields`），
  旧/新客户端传入多余字段不会报错。
- 服务端能力通过 `Capabilities` 返回，客户端按需启用。

## 测试

```bash
go test ./...
```

覆盖场景：

- 并发会话隔离（断点、状态、事件互不影响）
- 断点幂等性与重新附加恢复（含命中计数、无重复暂停）
- 步进边界（逐语句/逐过程/逐跳出、并发任务不被误停、暂停任务不推进）
- 异常捕获（未捕获异常终止、异常断点暂停、崩溃 fatal 区分）
- 超时与取消（求值取消、事件超时、有界队列、乱序/重复事件）
- 权限控制（敏感变量越权拒绝并审计、授权读取、嵌套惰性）
- 协议兼容（旧客户端默认字段、版本协商、未知字段容忍、完整流程）

## 包结构

| 包 | 职责 |
|----|------|
| `runtime` | 确定性脚本运行时：值、程序、任务、目标、调试钩子接口 |

| `protocol` | JSON 线协议：类型、编解码、版本协商、请求分发 |
