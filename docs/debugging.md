# 运行时调试服务

本仓库提供一套**纯进程内**的运行时调试能力：`vm` 包是脚本运行时（栈式虚拟机），
`debug` 包是调试服务。被调试目标与调试服务运行在同一进程内，不依赖任何外部服务，
所有结论可通过 `go test ./...` 在本地稳定复现。

## 架构

```
编辑器插件 / 开发者控制台
        │  (进程内 Go API)
        ▼
   debug.Service ── 实现 vm.Hook ──▶ vm.VM (目标)
        │                                │
   debug.Session (每个客户端一个)    vm.Task (执行单元, goroutine)
```

`Service` 注册若干目标（`RegisterTarget(name, *vm.VM)`），客户端通过
`Attach(AttachRequest{Target: ...})` 建立会话。服务以钩子身份挂在 VM 上，
在每条指令边界（`OnStep`）、任务开始/结束、未捕获异常时收到回调。

## 会话生命周期

```
Attach ──▶ attached ──Detach()──▶ detached
                │
                └──Terminate()──▶ terminated
```

- **建立/附加**：`Attach` 返回 `*Session`。附加时会按既定策略恢复断点（见下）。
- **分离（Detach）**：会话持有的所有暂停立即释放，**目标按自身节奏继续运行，
  语义状态不受任何影响**；会话事件通道关闭，之后不再收到任何事件。
- **结束（Terminate）**：与分离相同的释放语义，状态标记为 `terminated`。
  已结束的会话上的一切操作返回 `ErrSessionClosed`。
- **并发会话**：同一目标可附加多个会话。每个会话的断点集合、步进状态、
  事件流、帧 ID 空间完全隔离。一个任务被暂停时，**所有**请求停止的会话
  都恢复（Continue/Step）之后任务才继续推进。

## 断点语义

- **行断点**：按 `(函数名, 行号)` 定位。命中判定是确定性的：只在**行首指令**
  （statement boundary）判定，因此一行无论编译为多少条指令，每次执行该行
  **恰好停止一次**，不会重复暂停或丢失命中。
- **条件断点**：`Breakpoint.Condition` 是一个无副作用表达式（见求值一节），
  在命中行以当前帧局部变量为作用域求值，结果为 `true` 才停止。
  **条件求值出错时确定性视为不命中**。
- **幂等性**：`SetBreakpoints` 是全量替换；相同 `(函数, 行号)` 的断点重复设置
  保留原 ID，不产生重复停止。`RemoveBreakpoint` 对不存在的 ID 是 no-op。
- **恢复策略**：会话设置断点时同步写入目标的持久 profile；会话分离后 profile
  保留，**新会话附加时自动继承该 profile**（含条件与稳定 ID）。

## 步进语义

- `StepInto`（逐语句）：推进到下一条语句边界，跟随函数调用进入被调用方。
- `StepOver`（逐过程）：推进到**同一或更浅调用深度**的下一条语句；
  被调函数完整执行，不会停在其中。
- 步进只作用于被步进的任务。跨 `Spawn` 产生的并发任务边界时行为确定：
  **兄弟任务不受影响、不会被误停**；被暂停的任务在所有持有会话恢复前
  不会推进任何指令。

## 调用栈、变量与求值

- `StackTrace(taskID)`：仅当任务被**本会话**暂停时可用（否则返回
  `ErrTaskNotPaused`），保证读到的是确定、一致的现场。
- `Variables(frameID, path)`：惰性取值。嵌套结构（map/list）只渲染一层
  （如 `map[2]`），通过 path 逐层展开，读取过程**无任何副作用**。
- `Evaluate(ctx, frameID, expr)`：无副作用表达式语言（字面量、标识符、
  算术/比较/逻辑、`.` 与 `[]` 访问），**没有函数调用**，不会改变被调试
  程序的语义状态。求值前复制局部变量快照。
  - 未定义符号返回可区分的 `ErrUndefinedSymbol`；语法错误、除零等各自
    返回普通错误，**会话不会因此崩溃**。
  - `ctx` 取消/超时立即中止求值并返回 `ctx.Err()`，会话不停留在中间状态。

## 事件与并发

- 事件经 `Session.Events()` 投递，类型：`stopped / continued / taskStarted /
  taskEnded / exception / overflow / terminated`，每条带单调递增 `Seq`。
- 事件队列**有界**（每会话 256 条）。积压时淘汰最旧事件并投递 `overflow`
  事件（携带累计丢弃数），内存与待处理队列不会无界增长；目标执行
  **不会因为消费者慢而阻塞**。
- 事件与目标推进并发进行；乱序/重复到达不会破坏会话状态（所有状态迁移
  在服务锁内完成，暂停释放幂等）。

## 异常与崩溃

- 目标抛出未捕获异常（`throw` 或运行时错误如除零、未定义变量）时，运行时
  **保留完整调用栈现场**，调试服务以 `ReasonException` 暂停任务
  （会话可用 `ExceptionBreak: false` 选择不暂停，仅接收 `exception` 事件）。
- 执行过程中的 panic 会被运行时恢复并**按未捕获异常同样处理**，进程不崩溃。
- `TaskState(taskID)` 返回 `running / paused / terminated`，崩溃后的会话
  可以明确区分"停在异常现场"与"已终止"。恢复异常暂停后任务终止，
  其错误可通过 `vm.Task.Err()` 读取。

## 权限与审计

- 会话角色：`admin` 或 `viewer`（缺省，最小权限）。
- 以 `secret_` 为前缀的变量名是**敏感变量**：
  - `viewer` 在变量列表中只能看到 `<restricted>` 占位；
  - 显式按路径读取或在表达式中引用敏感变量会被拒绝，返回
    `ErrPermissionDenied`；
  - 所有允许/拒绝的读取都写入服务的有界审计日志（`Service.Audit()`，
    容量 1024，满了淘汰最旧），越权尝试可审计。

## 协议兼容性

- 协议版本：`debug.ProtocolVersion`。所有新增字段均为可选
  （指针或 `omitempty`），旧客户端缺少新字段时按安全默认值工作：
  `Role` 缺省 `viewer`，`ExceptionBreak` 缺省 `true`。
- 未知 JSON 字段被忽略；事件结构新增字段不影响旧客户端解析。

## 运行测试

```sh
go test ./... -race -count=1
```

覆盖：并发会话隔离、断点恢复与幂等、步进边界（into/over、跨调用、
跨并发任务）、异常捕获与崩溃恢复、求值取消/超时、事件积压有界、
敏感变量权限与审计、协议向后兼容。
